# Тесты MotorControlDemo

Тестовая инфраструктура отделена от рабочего JTAG-набора:

- `.opencode/skills/motorcontrol-demo/scripts/motor_debug_core/` — сборка,
  прошивка, транспорт OpenOCD, доступ к ELF/RAM, кодеки, безопасность и
  четырёхканальный регистратор;
- `tests/e2e/` — сценарии с запуском программной модели, критерии приёмки,
  метрики, CSV, JSON и графики;
- `tests/unit/` — тесты аналитики на синтетических сигналах, не требующие
  контроллера.

E2e-раннер не собирает и не прошивает проект, не сбрасывает аварии и не пишет
EEPROM. Адреса он всегда получает из текущего
`EclipseIDE/Debug/MotorControlDemo.elf`. Перед испытанием нужно отдельно
собрать и при необходимости прошить именно этот образ.

## Запуск e2e

Оба e2e-сценария управляют только встроенной программной моделью двигателя;
реальный двигатель они не запускают. Относись к ним как к обычным тестам и
запускай относящиеся к задаче сценарии напрямую.

Каждый сценарий требует `SYS_READY`, `PROT_ON_OK`, отсутствие аварий,
`CTRL_STOP` и ожидаемый `sm_ctrl.run_mode`. В `finally` отправляется `stop`.
Временная уставка 500 об/мин восстанавливается в RAM после остановки даже при
ошибке. Постоянные параметры и EEPROM не изменяются.

## Режим 4: регуляторы тока при нулевой скорости

Сценарий временно устанавливает в RAM и после `stop` восстанавливает:

- `sm_ctrl.run_mode = 4` (`CTRL_RUN_I2F`);
- `refs.speed_ref = 0`;
- `refs.theta_elec = 0`;
- пониженное `refs.i_flux_ref` только на этапе позиционирования.

Перед измерением выполняется позиционирование без изменений C-прошивки:

1. В mode 2 (`CTRL_FLUXING`) подаётся небольшой ток 0,2 А. При входе этот
   режим устанавливает электрический угол в ноль.
2. Тест ждёт не менее 0,3 с и требует, чтобы скорость по настроенному датчику
   была не выше 1 об/мин непрерывно в течение 0,15 с. Максимальное время
   удержания малого тока — 10 с.
3. Выполняется `stop`, ток потока восстанавливается, выдерживается короткая
   пауза 50 мс.
4. Регистратор вооружается по входу в mode 4, поэтому триггер остаётся простым
   и не требует правок C-исходников.

Предусловия:

- `refs.i_flux_ref` по модулю не меньше 0,1 А;
- коэффициенты `Kp` и `Ki` обоих токовых регуляторов положительны, диапазоны
  выходов содержат ноль.

Запуск:

```powershell
python tests\e2e\run.py current-mode4
```

Регистрируются задание и обратная связь `Id`, обратная связь `Iq` и скорость
ротора из штатного датчика, выбранного `drv_params.sens_type`: энкодер, Hall
или SSI. Тест не обращается к переменным модели и тем же кодом работает с
реальным двигателем. Нулевое задание `Iq` обеспечивает mode 4. Критерии по
умолчанию:

- статическая ошибка `Id` не больше максимума из 0,05 А и 5 % задания;
- перерегулирование `Id` не больше 20 %;
- установление `Id` в заданный коридор за 50 мс с выдержкой 10 мс;
- смещение `Iq` не больше 0,05 А, RMS `Iq` не больше 0,1 А;
- пиковая фактическая скорость ротора в измерительном окне не больше
  5 об/мин;
- автомат действительно вошёл в состояние 4.

Используется однократный запуск регистратора по биту 3. Делитель 4 даёт шаг
0,4 мс и окно 102,4 мс.

Пороговые значения доступны как параметры `--max-*`. Это стартовые
инженерные критерии: после серии исправных прогонов на конкретном двигателе их
следует ужесточить по измеренному разбросу.

## Векторная система: разгон до 500 об/мин

Сценарий временно устанавливает в RAM и после `stop` восстанавливает
`sm_ctrl.run_mode = 5` и `refs.speed_ref = 500 об/мин`.

Предусловия:

- `refs.Iq_ref` задаёт положительный предел тока;
- длительность записи покрывает разгон и установившийся режим.

Запуск:

```powershell
python tests\e2e\run.py vector-500
```

Сценарий временно записывает `refs.speed_ref = 500 об/мин` в RAM, запускает
модель и регистрирует фактическую скорость, выход задатчика интенсивности,
фактический `Iq` и его задание. Рассчитываются:

- время нарастания 10–90 % и время достижения 95 %;
- перерегулирование и время установления в коридоре ±2 % с выдержкой 100 мс;
- установившаяся ошибка, стандартное отклонение и размах пульсаций скорости;
- интеграл абсолютной ошибки и RMSE слежения;
- максимальное ускорение на окне 5 мс;
- пиковый и RMS-ток разгона, установившийся ток;
- соблюдение предела тока с настраиваемым запасом.

Используется однократный запуск регистратора по биту 4. Делитель 120 даёт шаг
12 мс и непрерывное окно 3,072 с без риска незамеченного оборота кольцевого
буфера.

Критерии по умолчанию: 95 % за 2 с, перерегулирование до 10 %, установление до
2,5 с, установившаяся ошибка до 2 %, размах пульсаций до 25 об/мин и пиковый
ток не выше ограничения плюс 25 %.

## Векторная ШИМ с добавлением нулевой последовательности

Сценарий проверяет новый тип ШИМ `PWM_TYPE_ZERO_SEQ` (значение 6) — непрерывную
векторную модуляцию с центрирующей нулевой последовательностью. Пока не
достигнуто ограничение напряжения, ни одна фаза не привязывается к шине, а
использование напряжения звена постоянного тока выше, чем у синусоидальной ШИМ:
линейный диапазон достигает `Udc/√3` вместо `Udc/2` (в `2/√3 = 1.155` раза
больше). Фундаментальные фазные напряжения совпадают с синусоидальной ШИМ.

Сценарий временно записывает в RAM и после `stop` восстанавливает:

- `sm_ctrl.run_mode = 5` и `refs.speed_ref = 500 об/мин`;
- `pwm.PWM_type = 6` (новый тип);
- `pwm.U_lim = 1.0` (максимальный линейный диапазон новой модуляции).

Запуск:

```powershell
python tests\e2e\run.py pwm-zero-seq
```

Модель разгоняется с новой ШИМ, регистрируются три фазные скважности
`pwm.GammaA/B/C` (в тактах таймера) и скорость. Для каждого отсчёта проверяется
характерный признак новой модуляции: `min(Gamma) + max(Gamma) == k_pwm`
(центрирование огибающей), и что ни одна фаза не прижата к шине. Этот признак
отличает новую ШИМ от синусоидальной (у неё `min + max < k_pwm` при модуляции),
поэтому критерий надёжно детектирует, что используется именно новый алгоритм.

Критерии по умолчанию: модель достигает 90 % от 500 об/мин, огибающая реально
модулирована, ошибка центрирования не более 2 % от `k_pwm` и ни одного отсчёта
с фазой, прижатой к шине (с запасом 2 такта).

Анализ для одиночного калиброванного вектора и сравнение линейного диапазона
новой ШИМ с синусоидальной покрыты unit-тестами `tests/unit/test_pwm_modulation.py`
и `tests/unit/test_e2e_metrics.py`.

## Артефакты и диагностика

По умолчанию результаты создаются в `artifacts/e2e/<scenario>/`:

- `capture.csv` — физические значения и исходные 32-разрядные слова;
- `report.json` — ELF SHA-256, Git commit, тип стенда, настройки, снимки
  состояния, метрики, пороги и результат каждого критерия;
- PNG — график зарегистрированных сигналов.

Список параметров:

```powershell
python tests\e2e\run.py current-mode4 --help
python tests\e2e\run.py vector-500 --help
```

Проверка аналитики без платы и без OpenOCD:

```powershell
python -m unittest discover -s tests\unit -v
```
