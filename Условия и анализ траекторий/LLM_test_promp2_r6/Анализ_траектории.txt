4. КАЧЕСТВЕННЫЙ АНАЛИЗ НАБЛЮДАЕМОГО ПОВЕДЕНИЯ

Стратегия решения

Реализация использует отдельный модуль с накопительным состоянием. После
каждого `pwm.update()`:

- если `pwm.ULimitation != 0`, integral уменьшается на Ki;
- иначе integral увеличивается на Ki к нулю;
- integral ограничивается сверху нулём;
- нижняя граница равна `-refs.Iq_ref`;
- output передаётся в Id reference следующего быстрого цикла.

Это замкнутая обратная связь по бинарному признаку ограничения PWM, но не
полноценный PI-регулятор по величине ошибки напряжения. Пропорциональной части
нет; величины `pwm.U_mag - pwm.U_lim` алгоритм не использует.
[L13908-L13917]

Место интеграции

Место выбрано разумно:

- `fldWeak.output` читается перед `pid_id.calc`;
- `FldWeak_calc()` вызывается после `pwm.update()`;
- новое значение используется на следующей итерации;
- состояние сбрасывается при входе в два PMSM-векторных режима.

Это избегает вмешательства в прочие режимы и согласуется с тем, что
`ULimitation` вычисляется PWM-модулем после формирования напряжения.

4.3. ОГРАНИЧЕНИЯ СПЕЦИАЛИЗИРОВАННОГО ТЕСТА

1. Нет A/B OFF/ON

Нет двух запусков одинаковой финальной прошивки при `Enabled=0` и
`Enabled=1`. Поэтому тест не доказывает, что достижение 700 об/мин обусловлено
именно новым алгоритмом.

2. Base speed не проверяется

Тест не читает `drv_params.speed_nom` и не утверждает программно, что
700 об/мин выше базовой скорости. Название «above base speed» остаётся
предположением.

3. Нет фактического Id

Регистрируется `pid_id.pid_ref_reg3`, но не `pid_id.pid_fdb_reg3`. PASS
подтверждает отрицательную команду, а не реальный отрицательный ток.

4. Нет PWM/voltage diagnostics

Не регистрируются:

- `pwm.ULimitation`;
- `pwm.U_mag`;
- `pwm.U_lim`;
- напряжение DC link.

Нельзя проверить, что отрицательный Id появился именно при насыщении и
действительно снял ограничение напряжения.

5. Синтетический Iq reference

Для повторного использования `analyze_vector_500` в копию каждого sample
вставляется постоянное `iq_ref_a=current_limit`. Реальный выход speed PI
не измеряется. Метрика `peak_abs_iq_reference_a` поэтому не является
осциллограммой реальной уставки.

6. Нет полного тока

Проверяется только фактический Iq. При отрицательном Id полный ток равен
`sqrt(Id^2 + Iq^2)`, но ни реальный Id, ни полный вектор не контролируются.

7. Критерии изменены после FAIL

Цель и пределы изменены после неуспеха на 1000 об/мин. Это допустимо как
итеративная настройка, но снижает независимость acceptance test и требует
явно фиксировать окончательную спецификацию.


4.4. ТЕХНИЧЕСКИЕ РИСКИ FIRMWARE

1. Это не PI-регулятор

Структура содержит Ki, но не Kp. Управление — интегрирование знака бинарного
флага saturation.

2. `Id_max` не используется

Поле объявлено и имеет default 1,0, но нижняя граница integral задаётся через
`-refs.Iq_ref`. Изменение `fldWeak.Id_max` не влияет на результат.

3. Небезопасное отключение

При `Enabled=0` функция немедленно возвращается и не сбрасывает `integral` и
`output`. Если отключить модуль после накопления отрицательного Id, старая
отрицательная уставка продолжит подаваться в d-регулятор.

4. Нет гистерезиса и величины ошибки

Один флаг `ULimitation` переключает направление интегрирования на каждом
быстром цикле. Около границы возможна пилообразная модуляция Id.

5. Ограничение по Iq reference

Максимальный модуль Id равен текущему `refs.Iq_ref`, а не независимому
допустимому d-току или общему токовому кругу.

6. Нет ограничения полного тока

Speed PI может потребовать Iq до `refs.Iq_ref`, а field weakening одновременно
добавляет Id того же масштаба. Теоретически амплитуда может превысить лимит
вплоть до `sqrt(2) * refs.Iq_ref`.

7. Всегда включено по умолчанию

`Enabled=1`, но штатного CANopen-параметра, документированной настройки и
энергонезависимой конфигурации не добавлено.

8. Область применения

Алгоритм интегрирован только в два режима синхронной машины. Это разумное
ограничение, но финальный ответ должен явно говорить, что другие режимы
не покрыты.


5. АНОМАЛИИ И УГРОЗЫ ВАЛИДНОСТИ

1. Преждевременный первый финал

Агент завершил задачу после сборки и unit-тестов, хотя аппаратная функция
оставалась непроверенной. Продолжение стало возможным только после
пользовательского сообщения. [L176020-L176100]

2. Изменение acceptance после FAIL

После неуспеха на 1000 об/мин цель снижена до 700, а временные пределы
изменены. Финальный PASS корректен для новой спецификации, но не закрывает
исходную цель 1000 об/мин.

3. Нет независимого теста

Тот же агент пишет firmware, сценарий, критерии и затем адаптирует их по
полученным результатам.

4. Общий test helper изменён

Для поддержки нового сценария изменён `plot_vector_500`. Финальные базовые
тесты прошли, поэтому наблюдаемой регрессии нет, но изменение общего helper
увеличивает поверхность влияния.

5. Исходный commit не зафиксирован

Есть только ветка LLM_test. Точную исходную ревизию воспроизвести нельзя.

6. Интернет и другие репозитории

Нарушений не обнаружено. Все пути относятся к текущему проекту или штатному
VectorIDE/OpenOCD.

7. Делегирование

Не использовалось. Вся наблюдаемая работа выполнена одним агентом.

8. Context compaction

Не было.

9. Старые артефакты

Содержательных выводов из артефактов прошлых запусков не видно.

10. Очистка стенда

E2e-сценарии используют временные значения и проверяют восстановление run mode
и speed reference. Логи показывают `Stopped` после захватов. Это снижает риск
загрязнения состояния.

11. Финальный отчёт

Численные результаты не выдуманы и соответствуют инструментам. Основная угроза
— интерпретация: PASS на 700 доказывает отрицательную уставку и хорошее
слежение, но не причинную необходимость field weakening и не фактическое
ослабление потока.


6. ДЕЙСТВИЯ ПОСЛЕ ПЕРВОГО И ОКОНЧАТЕЛЬНОГО ЗАВЕРШЕНИЯ

После первого завершения:

- пользователь сообщает, что плата подключена;
- агент возобновляет ту же задачу;
- диагностирует состояние;
- прошивает firmware;
- исправляет тест;
- выполняет полную стендовую серию.

Это единственный post-completion эпизод и одно ручное вмешательство.

После окончательного ответа:

- сообщений нет;
- ветка не создавалась;
- commit не создавался;
- дополнительных сервисных действий нет.
