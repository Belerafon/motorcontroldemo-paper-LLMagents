4. КАЧЕСТВЕННЫЙ АНАЛИЗ НАБЛЮДАЕМОГО ПОВЕДЕНИЯ
=============================================

Стратегия: сначала локализовать контур СД (SM_Ctrl, режимы CTRL_RUN_VECTOR_SM / CTRL_RUN_VECTOR_SM_ENCODER_POS), понять единицы напряжения/тока (PID, PWM, IQ-math), затем встроить интегратор ошибки напряжения, задающий отрицательный Id. Долго рассматривал CANopen-флаг field_weakening_ena и отказался из‑за риска STATIC_ASSERT/OD; решил держать регулятор всегда включённым в двух SM vector-режимах, полагаясь на клип интегратора к 0 при запасе напряжения [рассуждения MSG26].

Поиск места интеграции: по именам файлов Ctrl/Park/Ud, чтение SM_Ctrl.c/h, структур TRefs/TDrvParams, pid_reg3, V_PWM_Module (U_lim, U_mag, UdCompEnable). IM-режимы сознательно не трогал (в рассуждениях — отдельный flux path).

Проверки: агент сам спроектировал только чтение фрагментов и поиск символов SM_Ctrl_FieldWeaken / SM_CTRL_DEFAULTS. Штатных сборочных, unit- и стендовых тестов не запускал. Обратной связи сборки, стенда и осциллограмм нет.

Код менял до какой-либо фактической проверки на железе/компиляторе: серия edit после изучения. После правок — только повторное чтение, не пересборка.

Финальное заявление [L5263–L5332]: реализация FieldWeaken как voltage-error PI, |U| из выходов токовых регуляторов vs pwm.U_lim·adc.Udc_meas, Id=p->fw_ui в двух SM-режимах, сброс на stop/entry. Журнал подтверждает успешные edit этих файлов и наличие функции в патче MSG32. Не подтверждены компиляция, прошивка и работа на стенде; утверждения «self-adjusts / automatically injects exactly the negative Id needed» — интерпретация алгоритма, не результат испытания.

Непродуктивные повторения: протяженный обход CANopen OD (MSG18–MSG28) без изменения OD. Преждевременное завершение относительно типичного цикла отладки привода: нет build/flash/test.

Копирование готового решения другого запуска: не видно (нет обращений вне <PROJECT_ROOT>, нет checkout чужих веток). Алгоритм собран по коду проекта.
