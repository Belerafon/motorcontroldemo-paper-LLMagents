4. КАЧЕСТВЕННЫЙ АНАЛИЗ НАБЛЮДАЕМОГО ПОВЕДЕНИЯ

Стратегия решения

Агент выбрал централизованную реализацию в SM_Ctrl. Один helper `SM_Ctrl_ApplyCurrentDecoupling()` вычисляет перекрестные feedforward-слагаемые, складывает их с выходами токовых PI и формирует дополнительную ошибку насыщения для `saterr_reg3Add`. Коэффициент `current_decoupling_k` вычисляется фоновым `SM_Ctrl_Slow_Calc()` из параметров двигателя. [L133-L145]

Это архитектурно лучше копирования формул в каждый case: fixed-point арифметика, saturation и диагностика собраны в одном месте.

Как искал место интеграции

Агент сначала находит все режимы, где `pid_id/pid_iq` напрямую передаются в `ipark.de/ipark.qe`, затем заменяет эти пары на helper. Итоговый grep показывает семь вызовов:
- один с speed=0;
- два с `rmp.output`;
- четыре с `cur_par.speed`. [L153-L186] [L264-L265]

Какие проверки спроектировал сам

Агент выполняет:
- анализ CANopen/IQ24 scaling;
- чтение PWM limiter и PID anti-windup;
- проверку знаков по V_MotorModel;
- git diff/diff --check/EOL;
- четыре успешные host-компиляционные проверки измененных единиц/подмножества;
- одну неуспешную compile-all проверку всего дерева;
- один ручной численный sanity-check коэффициента;
- финальный grep/status/numstat. [L36-L62] [L189-L265]

Штатных unit/e2e/аппаратных проверок нет.

Формулы и масштабирование

Итоговый helper реализует:
- `Ud_ff = -omega_e * Ls * Iq`
- `Uq_ff = +omega_e * Ls * Id`. [L139] [L255]

Коэффициент формируется в Q24 как `2*pi*freq_nom*Ls*I_nom/U_nom`; агент отдельно проверяет синтетический пример и получает ожидаемый знак/порядок величины. [L143-L145] [L246-L247]

Журнал также показывает, что агент исследует CANopen/Q24 представление Ls, поэтому выбор fixed-point масштаба не является чистой догадкой. [L36-L50]

Ключевая проблема 1: anti-windup не отражает фактический векторный limiter PWM

До реализации агент читает `PWM_Module_NormInput()`. Там после формирования alpha-beta задания рассчитывается модуль вектора, сравнивается с `pwm.U_lim`, и при превышении обе компоненты пропорционально уменьшаются. [L57-L62]

Новый helper ограничивает d и q независимо:
- d по `pid_id.pid_out_min/max`;
- q по `pid_iq.pid_out_min/max`;
а `saterr_reg3Add` формируется только из разности этого поканального ограничения. [L133-L139] [L255]

Эти ограничения неэквивалентны. Возможна ситуация, где `|Ud| < limit` и `|Uq| < limit`, но `sqrt(Ud^2+Uq^2) > pwm.U_lim`. Тогда helper считает, что saturation нет, а PWM позже уменьшает весь вектор. PI-интеграторы не получают соответствующую внешнюю saturation error.

Для исходной цели на высокой скорости это существенный риск, поскольку именно feedforward повышает требуемый модуль напряжения. Финальное утверждение о "передаче насыщения в anti-windup" подтверждено только для введенного поканального limiter, но не для реального downstream PWM vector saturation.

Ключевая проблема 2: скорость dq-системы для IM

Агент читает RotorObserver и видит режим, где рабочий угол формируется как:
`RotorObserver.theta_psi_elec + posspeedEqep.theta_elec`. [L98]

Тем не менее IM helper-вызовы получают только `cur_par.speed`. [L167-L178] [L255]

Производная `RotorObserver.theta_psi_elec`, то есть slip/скорость вращения потоковой системы относительно ротора, в feedforward не добавлена. Следовательно, для IM используется не доказанная скорость вращения dq frame. Физическая корректность IM cross-coupling компенсации журналом не подтверждена.

Ключевая проблема 3: общий Ls вместо отдельных Ld/Lq PMSM

В исследовании параметров агент видит отдельные `l_sd` и `l_sq` в модели синхронной машины. [L31-L41]

Итоговая реализация использует один `drv_params.Ls` одновременно для d- и q-перекрестных слагаемых. [L143-L145] [L255]

Для машины с Ld≈Lq это приемлемое приближение. Для салентной PMSM с Ld != Lq точный decoupling не реализован. Журнал не устанавливает, что целевой двигатель обязательно несалентный.

Back-EMF PMSM

Отдельное слагаемое `omega*psi_pm` не реализовано. В буквальном смысле задача требует компенсацию перекрестных связей, поэтому это не обязательно ошибка задания. Но для высокоскоростной динамики q-регулятор по-прежнему должен самостоятельно компенсировать скоростную противо-ЭДС.

Использование git history

Агент специально запускает:
- `git log --all --oneline -S"decoupl"`;
- `git log --all --oneline -S"drv_params.Ls"`;
- `git branch --all`. [L57-L58]

Вывод показывает старые commit metadata и remote-tracking branch. `git show`, checkout или чтение файлов из старых коммитов не выполняются. Поэтому доказательств копирования готового решения нет, но поиск потенциально похожего решения в истории является угрозой валидности эксперимента и должен учитываться отдельно.

Compile-all FAIL

Попытка host GCC проверить все C-файлы завершается множественными ошибками в `cood1.c`, `cood2.c`, `mbod.c` и USB `__packed`. [L242-L243]

Поскольку измененные `SM_Ctrl.c` и `SM_Sys.c` отдельно успешно проходят syntax/object compilation до и после этой попытки, журнал не связывает compile-all FAIL с внесенным decoupling patch. Но это означает, что агент не имеет доказательства полной host-сборки проекта.
