# Автоматическое ослабление поля СДПМ

## Назначение и область действия

Модуль `V_FieldWeakening` автоматически формирует отрицательное задание
`Id` при исчерпании доступного напряжения инвертора. Он включён только в
режимах синхронной машины:

- `CTRL_RUN_VECTOR_SM` (`run_mode = 5`);
- `CTRL_RUN_VECTOR_SM_ENCODER_POS` (`run_mode = 10`).

Асинхронные режимы не изменены: в них ослабление поля требует уменьшения
положительного тока намагничивания, а не отрицательного `Id`.

## Алгоритм

Расчёт выполняется в контуре 10 кГц по выходам регуляторов тока предыдущего
такта:

1. Вычисляется модуль требуемого вектора напряжения `sqrt(Ud² + Uq²)`.
2. При включённой компенсации напряжения ЗПТ учитывается `pwm.UdCorTmp`.
3. Выше `0,95 * pwm.U_lim` интегратор увеличивает отрицательный `Id`.
4. Ниже `0,90 * pwm.U_lim` интегратор плавно возвращает `Id` к нулю.
5. Ниже `0,8` номинальной скорости отрицательный `Id` также возвращается к
   нулю.
6. `Id` ограничивается настроенным минимумом и 95% от
   `sm_prot.Imax_protect` (расчётный верхний предел — 4 о.е.).
7. Допустимый `Iq` пересчитывается по окружности общего тока:
   `Iq_max = sqrt(Imax² - Id²)` и не превышает `refs.Iq_ref`.

При `stop` внутренний интегратор и задание `Id` обнуляются. При отключении
алгоритма предел `Iq` возвращается к прежнему `refs.Iq_ref`, поэтому
`DebugW2 = 0` даёт прямое A/B-сравнение с исходным управлением.

## Настройка и диагностика через CANopen

Используются существующие свободные объекты `Debug*`; профиль `cood.xml` и
сгенерированные `cood1.c`/`cood2.c` не изменялись.

| Объект | Представление | Назначение | Дефолт | Рабочий диапазон |
|---|---|---|---:|---:|
| `0x5174:0x0C` (`DebugW2`) | signed 32-bit integer | `0` — выключено, `1` — включено | `1` | `0..1` |
| `0x5174:0x0D` (`DebugW3`) | signed IQ24, scale 1 | усиление интегратора за такт 10 кГц | `0,0005` | рекомендуется `0,0001..0,002`; программный предел `0,01` |
| `0x5174:0x0F` (`DebugW4`) | signed IQ24, scale 1 | минимальный отрицательный `Id`, о.е. от `drv_params.I_nom` | `-0,5` | от допустимого для магнитов отрицательного тока до `0` |
| `0x5174:0x01` (`Debug1`) | signed IQ24, scale 1 | текущее задание `Id`, о.е. | — | только чтение |
| `0x5174:0x03` (`Debug2`) | signed IQ24, scale 1 | требуемый модуль напряжения после компенсации, о.е. | — | только чтение |
| `0x5174:0x05` (`Debug3`) | unsigned 16-bit | флаги состояния | — | только чтение |
| `0x5174:0x07` (`Debug4`) | unsigned 16-bit | `pwm.ULimitation` | — | только чтение |

Флаги `Debug3`:

- бит 0 — алгоритм включён;
- бит 1 — отрицательный `Id` активен;
- бит 2 — напряжение выше верхнего порога;
- бит 3 — `Iq` уменьшен общим токовым пределом;
- бит 4 — достигнут настроенный минимум `Id`.

`DebugW4` обязан учитывать допустимый размагничивающий ток конкретного
двигателя. Программное ограничение по `sm_prot.Imax_protect` защищает от
перегрузки по модулю тока, но не знает предел необратимого размагничивания
магнитов.

## Жизненный цикл параметров

Значения `DebugW2..DebugW4` задаются в `SM_Ctrl_Init` после инициализации
CANopen. Это скомпилированные безопасные дефолты и временные настройки RAM:

- изменение на ходу действует сразу;
- `stop` сбрасывает состояние алгоритма, но не ручки настройки;
- сброс контроллера возвращает скомпилированные дефолты;
- модуль не вызывает сохранение CANopen и не записывает EEPROM.

## Проверка

Базовые регрессии:

```powershell
python tests\e2e\run.py current-mode4
python tests\e2e\run.py vector-500
```

Проверка ослабления поля встроенной программной модели:

```powershell
python tests\e2e\run.py field-weakening
```

Сценарий временно задаёт 750 об/мин, регистрирует скорость, фактические
`Id/Iq` и загрузку по напряжению, затем гарантированно отправляет `stop` и
восстанавливает изменённые значения RAM.
